# Security policy

## Supported versions

The latest tagged release and the current `main` branch receive security
updates. Public-preview releases may include breaking fixes when a safe
migration requires one.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's private vulnerability reporting for this repository. Include:

- the affected file, workflow, or profile
- the expected and observed behavior
- reproduction steps or a minimal proof of concept
- the likely impact
- any safe mitigation you have already tested

You should receive an acknowledgement within seven days. A fix, advisory, or
coordinated disclosure timeline will follow after the report is reproduced and
assessed.

## Scope

Security reports may cover the applicator, project skill, copied workflows,
documented access-control patterns, or secrets handling. Vulnerabilities in
upstream frameworks and platforms should also be reported to the relevant
maintainer.
