# Convex profile

Choose this profile when the product has authenticated application data,
realtime behavior, collaboration, scheduling, search, AI workflows, storage,
or web and native clients sharing one backend.

## Minimum capabilities

- current Convex with TanStack Start scaffold
- typed public and internal Convex functions
- explicit validators and authorization decisions
- GitHub Actions CI
- coordinated Convex and Cloudflare deployment

## Expected scripts

```json
{
  "scripts": {
    "lint": "eslint .",
    "typecheck": "tsc -b",
    "test": "vitest run",
    "build": "vite build"
  }
}
```

Use the scripts generated by the current official scaffold when they differ.

## Environment

- `VITE_CONVEX_URL` for CI against an isolated development deployment
- environment-specific `CONVEX_DEPLOY_KEY`
- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`
- runtime secrets configured on the matching Convex deployment

Use separate `staging` and `production` GitHub environments. Never use a
production deploy key in CI checks, previews, or agent worktrees.

## Boundaries

- public functions validate input, identity, authorization, and return shape
- reusable database work and document mapping live in `convex/model/`
- pure rules remain framework-free
- external and nondeterministic work uses actions
- client-inaccessible work uses internal functions
- queries use indexes and bounded reads
- ordinary Convex calls are not proxied through Cloudflare

Do not wrap `ctx.db` in a repository interface that only renames Convex.
